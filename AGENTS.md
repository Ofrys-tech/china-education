# AGENTS.md

Инструкция для агентов, работающих в этом репозитории. Короткая версия: **делай маленькие проверяемые изменения, не ломай base path GitHub Pages, не выдумывай факты, не гоняй e2e ради правки текста.**

## 1. Сначала прочитай

1. Этот файл.
2. `docs/architecture.md` — карта проекта и границы.
3. Документ по задаче:
   - контент → `docs/content.md`
   - форма/заявки → `docs/leads.md`
   - картинки → `docs/assets.md`
   - внешний вид → `docs/design.md`
   - тесты/деплой → `docs/testing.md`, `docs/deployment.md`

Не открывай файлы наугад: используй поиск и читай диапазоны.

## 2. Команды

```bash
npm ci                 # один раз
npm run dev            # локально
npm run verify         # обязательный быстрый гейт (~10 сек)
npm run test:e2e       # только для behavior/navigation/form/a11y изменений
```

Что означает «быстро»: `verify` = Biome + `astro check` + 18 unit-тестов + манифест ассетов + сборка + HTML-проверки. Не добавляй в него Playwright, внешние ссылки и Lighthouse.

- Правка текста/цвета/отступов: достаточно `npm run verify`; e2e не нужен.
- Правка навигации, меню, формы, доступности, URL: `npm run verify` + `npm run test:e2e`.
- Правка контента: `npm test` (content-инварианты) + `npm run verify`.
- После генерации изображений: `npm run check:assets`.
- Перед запуском/крупным релизом: `npm run check:links` (сеть, не в CI по умолчанию).

Хуки: pre-commit форматирует staged-файлы Biome; pre-push запускает lint + типы + unit. Обойти при необходимости: `SKIP_SIMPLE_GIT_HOOKS=1 git push`.

## 3. Жёсткие правила

### Base path

Сайт живёт на GitHub Pages project site: `/<repo>/`. **Никогда не пиши внутренние ссылки как `href="/programs/"`.** Используй `withBase()` из `src/lib/url.ts`. Для canonical/JSON-LD — `absoluteUrl()`. После изменений в URL-хелперах проверь:

```bash
BASE_PATH=/china-education/ SITE_URL=https://ofrys-tech.github.io npm run build
BASE_PATH=/china-education/ npm run check:html
```

### Дизайн

- Цвета, шрифты, радиусы, тени — только из `src/styles/tokens.css` / `var(--…)`. Не хардкодь hex в компонентах.
- Новые повторяемые блоки — в `src/components/`, а не копипаста по страницам.
- Проверяй 390px и 1440px. Никакого горизонтального скролла.
- Уважай `prefers-reduced-motion`; не добавляй autoplay-видео и тяжёлые библиотеки.
- Контраст: обычный текст ≥ 4.5:1, крупный ≥ 3:1. На тёмном фоне используй `--color-red-light`, не `--color-red`.
- Дизайн — исследовательская накидка: не «закрепляй» случайные решения без запроса. Обсуждай через `/styleguide/` и скриншоты.

### Контент

- Не выдумывай партнёрства, отзывы, имена, гарантии, статистику и контакты.
- Стипендия/зачисление/виза — «решение принимает вуз/консульство», без гарантий.
- Стоимость — «ориентир», с оговоркой о годе и вузе.
- Не добавляй скрытые TODO/placeholder в видимый текст. Незавершённое — в задачу, не в прод.
- Схемы контента в `src/content.config.ts`; сборка упадёт при неверных полях — это хорошо.

### Заявки

- Endpoint — только публичный URL из `PUBLIC_LEAD_ENDPOINT`; никаких токенов и секретов в клиенте/репозитории.
- Не добавляй cookies, пиксели и трекеры без явного запроса.
- Валидация: `src/lib/leads/schema.ts`; payload: `src/lib/leads/payload.ts`; UI: `LeadForm.astro` + `lead-form.ts`.
- После правок формы обнови unit-тесты и прогони e2e (успешная отправка мокается через `https://lead.test`).
- Провайдер должен валидировать данные на своей стороне; статический сайт не является сервером.

### Изображения

- Модель по умолчанию: **`gpt-image-2`**, качество **`high`**, размер **`4096x4096`**, формат PNG, прозрачный фон.
- Инструмент: `xd://generate_image`. Полный контракт и подводные камни — `docs/assets.md`.
- Прозрачность на «чистой» генерации часто игнорируется. Сначала сгенерируй объект на однотонном фоне, затем сделай edits с `refs` и `background: "transparent"`. Проверяй альфу через `npm run check:assets`.
- Каждая картинка: файл в `src/assets/generated/`, запись в `manifest.json` (prompt, model, quality, size, background, alt, usage, createdAt), затем `npm run check:assets` и `npm run assets:preview`.
- Не используй логотипы вузов, лица реальных людей, чужие IP и «фото» без лицензии. Текст внутри картинок не генерируй — верстка остаётся в HTML.

### Производительность

- Никаких UI-фреймворков без необходимости. Интерактивность — маленькие TS-скрипты.
- 4K PNG не кладём в `public/`; импортируем из `src/assets` через `astro:assets`/`<Image>`.
- Не подключай шрифты/скрипты с внешних CDN. Шрифты уже self-hosted.
- Следи за размером JS: сейчас клиентский JS — только меню/reveal/форма/аналитика (опционально).

### Безопасность

- Секреты — только в GitHub Secrets/локальном `.env` (он в `.gitignore`).
- Не логируй персональные данные в консоль.
- Внешние ссылки — `rel="noopener noreferrer"` при `target="_blank"`.

## 4. Как добавить страницу

1. Создай `src/pages/<name>.astro` на `BaseLayout`.
2. `title` + `description` + при необходимости `jsonLd`.
3. Внутренние ссылки — `withBase`.
4. Если страница служебная — `noindex` и исключи из sitemap в `astro.config.mjs`.
5. `npm run verify`; проверь страницу в браузере (390/1440).

## 5. Definition of done

- [ ] Изменение работает в браузере, а не только компилируется.
- [ ] `npm run verify` зелёный.
- [ ] Для behavior-изменений — `npm run test:e2e`.
- [ ] Мобильная и десктопная версии проверены.
- [ ] Нет секретов, фейковых фактов, битых ссылок, `TODO` в UI.
- [ ] Новые тексты добавлены в `src/i18n/en`, а не в разметку.
- [ ] Документация обновлена, если изменился контракт/команда/деплой.
- [ ] После `git push` CI и Pages зелёные; live URL открывается.
